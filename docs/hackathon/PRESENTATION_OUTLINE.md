# ライフコンパス東京 — First Stage プレゼン資料骨子

**想定時間**: 2分  
**推奨枚数**: 6枚（表紙を含む）  
**画面比率**: 16:9  
**作成日**: 2026-08-22

> この資料では、実装済みの機能と利用予定の機能を区別する。オープンデータ表示・対話型AIは、実装完了前には「予定」「目指す体験」と表現する。

## 全体メッセージ

**平均値で焦らせるのではなく、制度上どこまで選べるかを示すことで、自分の人生を何度でも描き直せるようにする。**

## スライド構成

### 1. 表紙｜ライフコンパス東京（0:00–0:10）

**載せるもの**

- 作品名: ライフコンパス東京
- 一言: 「キャリアとライフイベントを、自分軸で描き直す」
- タイムライン画面の全景スクリーンショット

**話すこと**

「ライフコンパス東京は、キャリアとライフイベントを一つの時間軸で考え、自分らしいプランを描き直せるWebアプリです。」

### 2. 課題｜変化が重なると、人生の全体像が見えにくい（0:10–0:30）

**載せるもの**

- 「転職」「結婚」「出産」「育休」「復職」のカードを散らした図
- 中央に「一つを選ぶと、ほかはどう変わる？」
- 補足: カレンダーや表計算では、予定同士の影響を捉えにくい

**話すこと**

「転機が重なる時期には、キャリアかライフイベントかという二者択一のような不安が生まれます。しかし実際には、それぞれの予定は影響し合います。全体を見渡し、変化に合わせて考え直せる枠組みが必要です。」

### 3. 解決策｜予定を置き、つながりを保って描き直す（0:30–0:55）

**載せるもの**

- タイムラインの拡大スクリーンショット
- 依存関係の線と、イベントを動かした際の連動を示す矢印
- 3つの短いラベル: 「同じ時間軸」「つながりを可視化」「いつでも変更」

**話すこと**

「ライフコンパス東京では、仕事とライフイベントを同じタイムラインに置きます。イベント間のつながりを保つため、予定を動かしたときにも影響を把握できます。一度決めるためのツールではなく、変化に合わせて引き直し続けるためのツールです。」

### 4. デモ｜自分のライフプランが動き出す（0:55–1:15）

**載せるもの**

- 画面キャプチャ2枚、または10〜15秒の無音操作動画
  1. イベントを追加した状態
  2. 予定を動かし、関連イベントも変化した状態
- 画面上に小さく「公開デモ: my-career-app-559fd.web.app」

**話すこと**

「こちらが公開デモです。イベントを追加し、予定を動かすと、関連するイベントとの関係を見ながらプランを更新できます。利用者が自分の状況に合わせて、何度でも考え直せることを大切にしています。」

### 5. オープンデータ｜平均ではなく、制度上の上限を見せる（1:15–1:40）

**載せるもの**

- 中央に「平均値は表示しない、という設計判断」
- 左右にビフォー/アフター的な対比カード
  - ✕「あなたは平均より遅れています」（作らない機能）
  - ○「育休は制度上、子が2歳になるまで取れます（出典: 育児・介護休業法）」（作る機能）
- データセットカード: 東京都デジタルサービス局「子育て支援制度レジストリ」（CC BY、出典URL明記）
- 下部に「タイムラインの情報カードとAIの発話に使う予定」

**話すこと**

「東京都の子育て支援制度データを使いますが、平均値は画面に出しません。プロダクトオーナーから『平均と比べたら焦る』という指摘を受け、あえて出さないという設計判断をしました。代わりに見せるのは、育休が制度上どこまで延ばせるかといった『選べる余地』です。出典を確認できる形で示し、比較ではなく選択肢を広げる情報として使います。」

### 6. 目指す体験｜決めるのは、いつも本人（1:40–2:00）

**載せるもの**

- 左: 「東京都のデータ」
- 中央: 「対話型AI（実装予定）」
- 右: 「自分だけのタイムライン」
- 締めの一文: 「平均ではなく、選べる余地をコンパスに、自分らしい人生を描く」
- QRコードまたはデモURL

**話すこと**

「今後は、対話型AIが言葉になっていない考えを整理し、確認済みの制度上限を参照しながらタイムライン操作を支援する体験を目指します。AIも制度情報も正解を押し付けるものではありません。決めるのはいつも本人です。ライフコンパス東京で、自分らしい人生を描き直せる選択肢を届けます。」

## 制作ルール

- 1スライド1メッセージに絞り、本文は最大30〜35字×3行程度にする。
- スライド3・4は、説明図よりも実際の画面を主役にする。
- スライド5のデータセット名、提供元、CC BY 4.0表記は省略しない。詳細URLは資料末尾またはQR遷移先に置く。
- 画面に未実装のデータ表示・AI対話はモック画面で表現しない。実装前は概念図と「実装予定」のラベルを使う。
- 発表者はスライドを読み上げず、各「話すこと」を自然な口調に整えて合計2分以内に収める。

## 提出用スクリーンショット候補

1. タイムラインの全体像（作品の基本体験）
2. イベントの依存関係が見える状態（技術・アイデア）
3. 予定変更後の状態、またはイベント追加画面（Living Plan）

オープンデータ表示と対話型AIが実装できた場合は、3枚目をその画面に差し替える。その際、出典・ライセンスが画面内で確認できる状態を撮影する。
