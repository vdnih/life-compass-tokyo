# ADR-005: 制約チェックのクライアントサイド実行

**Date**: 2026-03-09
**Status**: 採用済み

## 背景

転職・産休・育休の制約チェックロジック（C-01, C-02, C-03）をどこで実行するかを決定する必要があった。選択肢はクライアントサイド（Flutterアプリ内）またはサーバーサイド（Cloud Functions等）。

## 決定

制約チェックはクライアントサイドで実行する。Cloud Functionsは使用しない。

## 理由

- MVP時点のイベント数（数十件規模）では、クライアントサイドの計算で性能要件（100ms以内）を十分に満たせる
- サーバーサイドに移すとCloud Functionsの導入・維持コストが発生し、オフライン動作もできなくなる
- 制約ルールはユーザーの入力データのみに依存するロジックであり、サーバー側に置く必然性がない

## 影響範囲

- `lib/features/timeline/logic/` 配下の制約チェックProvider
- インフラ構成: Cloud Functions不要（ADR記録時点でサーバーレス構成を維持）
