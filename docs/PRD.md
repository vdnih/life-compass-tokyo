# ライフプランアプリ プロダクト要件定義書 (PRD)

**Version**: 4.0
**Last Updated**: 2026-03-26
**Owner**: Architect Agent

## 1. プロダクトビジョン

女性が自身のキャリアとプライベートの両面から、ライフゴールを設定し、
そこから逆算して必要なイベントやタイミングを計画するためのタイムラインアプリ。

**コアコンセプト**: 「目標から逆算して、わたしの人生をデザインする。」

プロジェクトマネジメントのように、ゴール（マイルストーン）を設定し、
そこから逆算して必要なタスクやイベントを時系列に配置していく。
イベント同士の依存関係を可視化し、1つのイベントを動かすと関連イベントも連動して移動する。

## 2. ターゲットユーザー

- 20〜40代の女性
- キャリアとプライベートの両立を考えている方
- 人生の転機（転職、結婚、出産など）を見据えて計画を立てたい方
- 過去の経験を整理し、将来の選択に活かしたい方
- 産休・育休と転職のタイミングを戦略的に検討したい方
- **ライフゴールを設定し、そこから逆算して計画を立てたい方**

## 3. 機能定義

### 3.1. MVP（Phase 1 - リリース済み）

> **注意**: Phase 1 の機能はすべてリリース済み。変更する場合は影響分析が必要。

#### F-01: タイムライン表示
- 横スクロール型のタイムラインで、仕事（Work）とプライベート（Private）の2レーンを表示する。
- 年月ビュー（詳細）と年ビュー（俯瞰）の切り替えができる。
- 生年月日設定時、時間軸上に年齢を表示する。

#### F-02: イベント管理
- イベントの追加・削除ができる。
- イベント種別: 仕事（Work）/ プライベート（Private）
- 各イベントに設定可能な項目:
  - タイトル（必須、最大50文字）
  - 詳細（任意、最大500文字）
  - 開始年月（必須）
  - 終了年月（任意）
  - サブカテゴリ（種別に応じた選択肢、後述のF-02-SUBを参照）

#### F-02-SUB: イベントサブカテゴリ（女性キャリア対応）
- イベント種別ごとに、より具体的なサブカテゴリを選択できる。
- サブカテゴリに応じたアイコンとカラーバリエーションで視覚的に区別する。

| 種別 | サブカテゴリ | アイコン概要 | カラー |
|---|---|---|---|
| 仕事 (Work) | 入社・転職 | ビル / ブリーフケース | Blue 600 |
| 仕事 (Work) | 昇進・昇格 | 上矢印 / スター | Blue 400 |
| 仕事 (Work) | 産休取得 | ハート / カレンダー | Pink 300 |
| 仕事 (Work) | 育休取得 | チャイルド / カレンダー | Pink 200 |
| 仕事 (Work) | 復職 | リフレッシュ / 矢印 | Blue 500 |
| 仕事 (Work) | 退職 | ドア / 出口 | Grey 500 |
| 仕事 (Work) | 目標 | フラッグ | Blue 300 |
| 仕事 (Work) | その他 | ワーク | Blue 200 |
| プライベート | 結婚 | リング | Orange 400 |
| プライベート | 妊娠・出産 | ベビー / ハート | Pink 400 |
| プライベート | 育児 | ファミリー | Orange 300 |
| プライベート | 介護 | ハンド / ハート | Purple 300 |
| プライベート | その他 | パーソン | Orange 200 |

- **設計根拠**: 女性のキャリア検討では、仕事とプライベートの境界にまたがるイベント（産休・育休など）が重要な意思決定要素となる。仕事側に「産休取得」「育休取得」「復職」を、プライベート側に「妊娠・出産」「育児」を設けることで、同一イベント（出産）の仕事面とプライベート面の両方を記録できる。

#### F-03: プロフィール設定
- ユーザー名の設定（最大20文字）
- 生年月日の設定（年齢自動計算に使用）

#### F-10: ライフイベント制約の可視化（基本版）
- **転職と産休・育休の制約表示**:
  - 「入社・転職」イベント登録時、そのイベントの開始日から1年後の日付を「産休・育休取得可能日」としてタイムライン上にマーカー表示する。
  - 算出根拠: 育児・介護休業法では、労使協定により入社1年未満の従業員を育休の対象外とできる。
- **制約の自動チェックと警告表示**:
  - 「入社・転職」イベントから1年未満の期間に「妊娠・出産」または「産休取得」イベントが存在する場合、警告メッセージを表示する。
  - 警告文例: 「転職から1年未満のため、育休が取得できない可能性があります」
  - 警告の表示場所: イベント追加時のダイアログ内 + タイムライン上の該当イベントカードにアイコン表示
- **逆算ガイドライン**:
  - 「妊娠・出産」イベント登録時、逆算して「この時期までに転職すべき」という目安日をタイムライン上に表示する。

#### F-MVP-DATA: データ永続化（ローカル）
- MVPではインメモリ（アプリ再起動でデータ消失を許容）
- Repository層のインターフェースはFirestore移行を見据えた設計にしておく

### 3.2. Phase 2（目標逆算機能）

> **テーマ**: 目標から逆算して人生を設計する機能群。イベント間の依存関係とゴールテンプレートが中核。

#### F-06: イベント編集
- 既存イベントのタイトル、詳細、日付、カテゴリ、ステータスを変更できる。
- 日付変更時は依存関係に基づくカスケード移動が発動する（F-22参照）。

#### F-20: イベント依存関係
- イベント同士を依存関係で紐付けられる。
- 依存関係の種類:
  - **前提（prerequisite）**: AがBの前提条件。AはBより前に完了している必要がある。
  - **結果（consequence）**: AによりBが発生する。Aの後にBが自動的に続く。
  - **期限（deadline）**: AはBのNヶ月前が期限。Bの日付からNヶ月前がAの期限。
  - **連動（companion）**: AとBは常に一定間隔を維持する。
- 時間的オフセット（Nヶ月前/後）を設定可能。
- 依存関係はゴールテンプレートから自動生成されるか、ユーザーが手動で設定できる（手動設定は将来Phase）。
- 循環依存は検出して拒否する。

#### F-21: ゴールテンプレート
- 主要ライフゴールを選ぶと、関連イベント群がテンプレートとして一括生成される。
- ユーザーはゴールの目標日を設定するだけで、逆算された関連イベントがタイムラインに配置される。
- 生成後のイベントは個別に編集・削除可能。
- **Phase 2 MVP**: 「出産」テンプレートのみ（詳細はセクション6参照）。

#### F-22: ドラッグ&ドロップ移動
- タイムライン上のイベントをドラッグで移動できる。
- **操作方法**: イベントカードを長押しでドラッグ開始（横スクロールとの競合を回避）。
- 依存関係を持つイベントを移動すると、関連イベントが連動して移動する（カスケード移動）。
- **カスケード移動アルゴリズム**:
  1. 対象イベントの日付を新しい日付に更新
  2. 移動差分（deltaMonths）を計算
  3. 依存グラフから、対象イベントを起点に到達可能な全イベントを取得
  4. トポロジカル順序で各依存イベントの日付をdeltaMonths分シフト
  5. 全移動後に制約チェッカーを再実行
  6. 制約違反があればUIに警告表示（移動自体はブロックしない）

#### F-23: 依存関係の可視化
- 関連イベント間をコネクタ線で結んで可視化する。
- 依存タイプに応じた線のスタイル:
  - 前提/結果: 実線 + 矢印
  - 期限: 点線 + 矢印
  - 連動: 実線（矢印なし）
- 同一ゴール起点のイベント群は同じ色でグルーピング表示する。

### 3.3. Phase 3（将来構想 - スコープ外）

- F-04: ライフイベントカテゴリのさらなる拡充（ユーザー定義カテゴリ）
- F-05: 将来計画モード（過去と将来の視覚的区別、ステータス付与）
- F-07: Firebase連携・データ永続化（認証、Firestore同期、マルチデバイス対応）
- F-08: メモ・振り返り機能
- F-09: テンプレート機能（転職、起業など追加テンプレート）
- F-11: キャリアブランク影響の可視化
- F-12: 制約チェッカー（高度版）
- F-24: 逆算タイムライン表示（ゴールから現在に向かって「何をいつまでにすべきか」を逆順で表示するモード）
- 高度な分析機能:
  - 年収推移シミュレーション（育休中の給付金計算を含む）
  - ライフプランの複数パターン比較
  - キャリアカウンセラー監修のアドバイス機能

## 4. 画面構成

### 4.1. タイムライン画面（メイン画面）
- **AppBar**: アプリ名 + ユーザー名(年齢) + ビュー切替ボタン + プロフィール設定アイコン
- **Body**: 横スクロールタイムライン（上段: 仕事レーン / 下段: プライベートレーン）
  - 「入社・転職」イベントから1年後の位置に「育休取得可能」マーカーを表示
  - 制約違反のあるイベントカードには警告アイコンを表示
  - **[Phase 2]** 依存関係のあるイベント間にコネクタ線を表示
  - **[Phase 2]** イベントカードは長押しでドラッグ移動可能
- **FAB**: イベント追加ボタン（+アイコン）
- **[Phase 2]** ゴール設定ボタン（AppBarまたはFAB長押しメニュー）

### 4.2. イベント追加ダイアログ
- 種別選択（仕事 / プライベート）
- サブカテゴリ選択（種別に応じた選択肢を表示）
- タイトル入力フィールド
- 詳細入力フィールド
- 開始年月ピッカー
- 終了年月ピッカー（任意）
- **制約チェック結果表示エリア**: イベント保存前に制約チェックを実行し、警告があれば表示する。ユーザーは警告を確認した上で保存可能（ブロッキングではない）。

### 4.3. プロフィール設定ダイアログ
- ユーザー名入力フィールド
- 生年月日ピッカー

### 4.4. ゴール設定ダイアログ [Phase 2]
- **テンプレート選択**: 利用可能なゴールテンプレート一覧から選択（Phase 2 MVPでは「出産」のみ）
- **ゴール日設定**: 目標日（yyyy-MM）のピッカー
- **関連イベントプレビュー**: テンプレートから自動生成されるイベント群の一覧表示
  - 各イベントのタイトル、カテゴリ、予定日（ゴール日からの逆算）
  - イベント間の依存関係の視覚的表示
- **確認・適用ボタン**: プレビューを確認後、一括でタイムラインに追加
- **キャンセルボタン**: テンプレート適用を中止

## 5. 制約チェックルール定義

以下の制約ルールを実装する。

| ID | 条件 | メッセージ種別 | メッセージ | Phase |
|---|---|---|---|---|
| C-01 | 「入社・転職」から1年未満に「妊娠・出産」または「産休取得」が存在 | 警告 (Warning) | 「転職から1年未満のため、育休が取得できない可能性があります」 | Phase 1 ✅ |
| C-02 | 「妊娠・出産」が登録されたが、1年以上前に「入社・転職」が存在しない | 情報 (Info) | 「出産予定の1年前までに転職を完了しておくと、育休取得がスムーズです」 | Phase 1 ✅ |
| C-03 | 依存関係のオフセット期間が確保されていない（例: 前提イベントが結果イベントの後にある） | 警告 (Warning) | 「{sourceEvent}と{targetEvent}の間に必要な期間（{offsetMonths}ヶ月）が確保されていません」 | Phase 2 |

- 制約チェックはクライアントサイドで実行する（サーバーサイドロジック不要）。
- 制約チェック結果は永続化しない（イベント一覧と依存関係から毎回算出する）。
- **設計根拠**: 制約結果をDBに保存するとイベント変更時の整合性維持が複雑になる。イベント数がMVP時点で数十件規模のため、毎回算出しても性能問題は発生しない。

## 6. ゴールテンプレート定義（F-21）

### 6.1. 出産テンプレート

ゴール日を `T` とした場合の自動生成イベント:

| # | 自動生成イベント | カテゴリ | 日付 | 終了日 | 依存タイプ | 説明 |
|---|---|---|---|---|---|---|
| 1 | 妊活開始 | private (その他) | T - 12ヶ月 | - | prerequisite | 出産の1年前を目安に妊活開始 |
| 2 | 転職リミット | work (jobChange) | T - 12ヶ月 | - | deadline | 育休取得のため、出産1年前までに転職完了が必要 |
| 3 | 海外旅行リミット | private (travel) | T - 4ヶ月 | - | deadline | 安定期を考慮した海外旅行の最終機会 |
| 4 | 産休開始 | work (maternityLeave) | T - 2ヶ月 | T | consequence | 産前6週間（約1.5ヶ月）から産休取得 |
| 5 | 出産（ゴール） | private (childbirth) | T | - | - | ゴールイベント本体 |
| 6 | 育休 | private (childcareLeave) | T | T + 12ヶ月 | consequence | 出産後〜最大1年間の育児休業 |
| 7 | 復職 | work (returnToWork) | T + 12ヶ月 | - | consequence | 育休終了後の職場復帰 |

- テンプレート適用後、各イベントは個別に編集・削除可能。
- ゴール日（出産予定日）を移動すると、全関連イベントがカスケード移動する。
- テンプレート定義はアプリ内にハードコードする（Firestore非永続化）。

## 7. 非機能要件

- レスポンシブ対応（スマートフォン + タブレット + Web）
- オフラインファースト（Phase 3のFirebase連携時もローカル優先）
- アクセシビリティ配慮（十分なコントラスト比、スクリーンリーダー対応）
- 制約チェックの応答時間: 100ms以内（クライアントサイド計算のため十分達成可能）
- カスケード移動の応答時間: 200ms以内（依存グラフの探索 + 一括更新）

## 8. デザイン方針

- 仕事イベント: ブルー系（サブカテゴリによりバリエーションあり）
- プライベートイベント: オレンジ系（サブカテゴリによりバリエーションあり）
- 産休・育休関連: ピンク系（仕事・プライベートの境界にあるイベントの視覚的統一）
- 制約警告: Amber系 (`Colors.amber`)
- 制約情報: Light Blue系 (`Colors.lightBlue`)
- **ゴールイベント**: Purple 400（目標であることを視覚的に強調）
- **依存関係線**: Grey 400（デフォルト）、ゴール起点のグループ色で色分け
- 基調: blueGrey（MVPはデフォルトテーマ、Phase 2以降で温かみのあるトーンに変更検討）
- シンプルで直感的なUI
