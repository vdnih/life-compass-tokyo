## 1. イベント種別の表現方針

イベント種別は **規定ライフイベントカタログ**（`catalogId`）で識別する（ADR-010 参照）。
従来の `EventCategory` enum は v2.0 で廃止した。

各カタログ項目は **グループ** に属する。グループ enum:

| グループ値 | 表示名 | 主なテーマ |
|---|---|---|
| `marriage` | 結婚 | 同棲・プロポーズ・両家顔合わせ・入籍・結婚式・新婚旅行など |
| `childbirth` | 出産 | 妊活・妊娠・産休・出産・育休・復職 |
| `career` | キャリア | 入社・転職・昇進・起業・資格・副業・退職 |
| `lifestyle` | 住まい | 引越し・賃貸契約更新・住宅購入検討・住宅購入・リフォーム |
| `travel` | 旅行 | 海外旅行・長期旅行・ワーケーション・留学 |
| `learning` | 学び | 資格勉強開始・学位取得・語学留学 |
| `money` | お金 | NISA開始・iDeCo開始・保険見直し |

**初版スコープ外**: 介護グループは含めない（PDR-005 参照、ターゲット 20代後半〜30代前半女性）。

## 2. 制約チェックルール

制約チェックはクライアントサイドで実行する（ADR-005 参照）。
制約チェック結果は永続化しない（ADR-002 参照）。
制約には **強度（strength）** がある（ADR-012 参照）。

| 強度 | 意味 | UI |
|---|---|---|
| **hard** | 物理的・法的・論理的に成立しない順序の前提 | 赤フィードバック |
| **soft** | 慣習・準備期間として推奨される前提 | 黄フィードバック |

いずれも **配置はブロックしない**（Value 4: Empowerment, not Direction）。
個別の hard / soft ルールは §4 の各カタログ行に定義する。

### 2.1. メッセージ文言の基準

制約・推奨メッセージは事実の情報提供に留め、行動指示・推奨を含む表現（「〜すべき」「〜が必要」「リミット」等）は使わない（Values: Empowerment, not Direction）。

- 使う: 「〜の目安です」「〜が確保できると◯◯しやすくなります」「一般的には〜が多いです」
- 使わない: 「〜すべき」「〜しておく」「〜が必要」「リミット」「〜できません」

### 2.2. 旧 C-01〜C-03 の扱い

| 旧ID | 旧条件 | v2.0での扱い |
|---|---|---|
| C-01 | 「入社・転職」から1年未満に「妊娠・出産」または「産休取得」が存在 | §4 `pregnancy` と `childbirth` の soft 先行ルール（`job-change` から12ヶ月以上）に統合 |
| C-02 | 「妊娠・出産」が登録されたが、1年以上前に「入社・転職」が存在しない | C-01 と裏表のため統合済み |
| C-03 | 依存関係のオフセット期間が確保されていない | カタログ静的ルール + ユーザー定義依存関係の両方で hard / soft を判定する形に拡張 |

## 3. ゴールテンプレート定義

テンプレート定義はアプリ内にハードコードする（ADR-004 参照）。
テンプレート内の各 `TemplateEvent` は `catalogId` を参照する（ADR-010）。

v2.0 では出産テンプレートに加え、結婚テンプレート / 転職テンプレート / 住宅購入テンプレートを Wave 4 で追加予定。
具体的なテンプレート定義は `lib/features/timeline/data/goal_template_data.dart` を参照（コードを正とする）。

## 4. 規定ライフイベントカタログ

### 4.1. 全体方針

- カタログ定義はアプリ内にハードコード（ADR-010 / ADR-004 と同方針）。
- すべてのIDは **kebab-case**。同一IDの重複は禁止。
- `hardRules` / `softRules` の `predecessorCatalogId` は **本SPEC内で定義された他のID** を指す（孤立参照禁止）。
- `predecessorCatalogId` が指す先行イベントが **未配置** の場合は警告対象。
- 予算プリセット（中央値、円）は **ざっくり目安**。ユーザーは自由に上書きできる。Value 1: Compass, not a Mirror に従い、ランキングや他者比較は行わない。
- `期間（durationMonths）` は推奨表示期間。null = 単発イベント（終了日なし）。

### 4.10. 制約チェッカーへの統合

旧 C-01 / C-02 の入社・転職と出産の関係は、§4.3 の `pregnancy` および `childbirth` の soft 先行ルール
（`job-change` から12ヶ月以上）に統合された。`constraint_checker_provider` は SPEC §4 のカタログ静的ルール
を読み込み、配置済みイベント間の前後関係から hard / soft 違反を導出する。
