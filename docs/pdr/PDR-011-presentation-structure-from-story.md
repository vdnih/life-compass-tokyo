# PDR-011: プレゼン資料の構成を、全体メッセージの要素と1対1に組み直す

**Date**: 2026-08-30
**Status**: 採用済み
**Owner**: プロダクトオーナー / AI Coding Agent

---

## 背景

きっかけは、プレゼン資料スライド2の対比数値「希望34% ↔ 現実32%」が分かりづらい、という
プロダクトオーナーからの指摘だった。一次資料（東京都「男女平等参画に関する世論調査」）を
確認したところ、数字そのものに2つの問題があった。

1. **旧データだった。** 令和2年11月調査の値だが、同じ調査の最新版（令和7年8月調査）が
   令和8年3月に公表済みだった。
2. **読み方が誤っていた。** 34%は「希望」の最頻値（仕事・家庭生活・個人の生活すべて）、
   32%は「現実」の最頻値（仕事を優先）であり、**別の選択肢**。「希望34%が現実には32%に
   減った」という関係ではない。発表者ノートの「希望は34%ある一方、現実に叶うのは32%でした」
   は一次資料の誤読だった。

数字を直すために資料全体を見直したところ、より大きな問題が見つかった。

**[PDR-010](PDR-010-messaging-institution-as-instrument.md) で確定した全体メッセージの要素の
一部が、資料のどこにも現れていなかった。** 特に次の部分が全スライドから欠落していた。

> 私自身、今世の中にあるデータで得られる示唆よりも、女性はもっと働きたいし社会で成功したいし、
> 起業したいくらい熱い層も多いのではないかと思っている。ただ、どうしても家庭との両立で諦めざるを
> 得ない状況の人が多いと感じている。

これはプロダクトの動機そのものだが、6枚のスライドで一度も語られていなかった。

あわせてプロダクトオーナーから、課題を2つに分けて語りたいという整理が示された。

> ・家庭もキャリアも全力で頑張りたい女性がいる
> ・こういった方は日々悩みや不安を抱えている
> ・そのうちの一つとして制度を知らないというのがある
> ・もう一つは女性は男性よりも社会進出しづらい＆家庭の方が向いているみたいにいわれがちなど
> ・だからこのアプリでライフプランをシミュレーションして、家庭でシェアしよう！
>   ＆男性も女性はこうやって生きているということを知った方が良いよね！

さらに、事務局配布資料「提出資料について」「First Stage - 事前確認資料」を確認したところ、
現行資料に**2つの要件違反**があった。

- 資料内容の必須項目「チーム（もしくは個人）の紹介」が資料に無い
- 「当日はライブデモは一切できない。動くデモは動画として埋め込むこと」とあるのに、
  スライドの登壇メモが「実機でサインインして見せる」となっていた

## 決定

**全体メッセージ（`PRESENTATION_OUTLINE.md` の確定稿）は一言も変えない。**
その要素を運びきるために、スライド構成・各スライドの主張・見出しを組み直す。

### 1. 課題を2枚に分ける（本編6枚 → 7枚）

| # | スライド | 対応する物語の要素 |
|---|---|---|
| 1 | 表紙（チーム紹介を含む） | — |
| 2 | 課題①「女性は家庭の方が向いている」と言われる | 制約がある／諦めざるを得ない |
| 3 | 課題② もうひとつの悩み。使える制度を、知らない | 知らないまま選択肢が狭まる |
| 4 | 解決策 何が選べるかを知って、自分で決める | 制度上どんなライフプランが選べるかを示す |
| 5 | デモ 何度でも立て直せる | 適宜修正も可能／何度でも立て直せる |
| 6 | 広がり 一つの画面を、家庭で。男性が体験する | 家庭で共有／男性がやってみる |
| 7 | 締め このデータが、次の施策を動かす | データが施策を動かすことを願う |

課題②は、課題から解決策への橋になる。従来は課題からいきなり解決策に飛んでいた。

### 2. 各スライドの主張に一次データを1つずつ添える

スライドの面に出す数値は1〜2個に抑え、残りは「話すこと」と質疑用に回す。

- スライド2: 「育児は女性の方が向いている」68% ↔「男性の方が向いている」7%
  （世論調査 令和7年8月調査, n=1,615）。補足として、事業所が挙げる課題1位「管理職を希望する
  女性従業員が少ない」46.4% ↔ 従業員女性が挙げる1位「家庭責任が重いイメージ」69.4%
  （男女雇用平等参画状況調査 令和7年度）。**この食い違いが「望んでいないのではなく、
  諦めざるを得ない」という見立てを一次データで支える。**
- スライド3: 自分の職場に制度があるか「わからない」— 産前産後休暇6.0% / 通院休暇制度33.9% /
  妊娠障害休暇42.8% / 出産障害休暇47.3%（同調査 従業員 n=1,076）
- スライド6: 母性保護8項目すべてで男性の「わからない」が女性より高い
  （出産障害休暇: 男性52.6% / 女性42.4%）。従来の脚注「男性の育休取得率61.2%」は上昇中の
  数字であり、「男性に制約の多さを痛感してもらう必要がある」という主張の裏付けとしては
  向きが逆だった。61.2%は話すことに移す
- スライド7: 行政に力を入れてほしいこと1位「家事・育児や介護中の人への家庭と仕事の両立支援」64%
  （世論調査 令和7年8月調査）

### 3. 見出しの主語を本人側に統一する

PDR-010 で「制度は本人が使う道具として述語側に置く」と決めたが、見出しに反映漏れがあった。

- 表紙「制度を知って、自分の人生を自分で描く」→「自分の人生を、自分で描き直す」
- 解決策「使える制度を、出典付きで手渡す」→「何が選べるかを知って、自分で決める」
- 解決策の3ラベルの順を「決めるのは自分」「同じ時間軸」「出典付きの事実」に入れ替える

これは方針変更ではなく、PDR-010 の反映漏れの解消。

### 4. 令和2年度の世論調査を資料から全面的に外す

旧データであり、かつ引用の仕方が誤読だったため。提出フォーム4-1のURLも令和7年8月調査に
差し替える。

### 5. 事務局要件への対応

- チーム紹介を**表紙に置く**。本編2分を圧迫しないよう独立スライドにはしない
- ライブデモ禁止を、スライド5の登壇メモと `PRESENTATION_OUTLINE.md` の制作ルールに明記する

### 6. 発表台本を独立したファイルにする

`docs/hackathon/PRESENTATION_SCRIPT.md` を新設し、読み上げ用の原稿・話者分担・尺の見積もりを置く。
2人チームのため、**前半（表紙〜課題②）をあかり、後半（解決策〜広がり）をりょう、
締めを再びあかり**が話す。プロダクトオーナーの言葉で始まり、プロダクトオーナーの言葉で終わる。

台本は625字。日本語のプレゼン発話は毎秒5〜6字が目安のため、標準ペースで約1分54秒。
2分の制限に対する余裕は6秒程度しかないため、超過時の削り順も台本に明記した。

骨子の「話すこと」・台本・スライドの発表者ノート（`build_slides.py` の `set_notes`）は
**同じ文言を保つ**。3箇所に散らばるが、どれか1つを直したら他も直す。

## 検討したが採らなかった案

**スライド2の数字だけを差し替える最小案。** 変更範囲は小さいが、物語の要素の欠落と
見出しの主語のズレが残るため採らなかった。指摘の出発点は数字1個だったが、原因は資料全体の
構成にあった。

**課題を1枚にまとめて6枚を維持する案。** 2分の制約には有利だが、
「思い込み」と「制度の未認知」は性質の違う悩みで、1枚1メッセージの制作ルールに反する。
また課題から解決策への橋が失われる。ただし**通しの実測で2分に収まらなかった場合は、
この案に後退する**。

**チーム紹介を独立スライドにする案。** 事務局要件は満たせるが、2分のうち10秒前後を
消費する。表紙に置けば要件を満たしつつ時間を使わずに済む。

## 残課題

以下は収録前に必要な作業。Issue を立てて管理する。

- 通しで2分に収まるかの実測（超過すると強制終了となるため必須）
- 提出用画面キャプチャの再出力（現在の `slides/assets/` は1404×806pxで、
  事務局要件の1600×900px以上を満たしていない）
- デモ動画の収録とスライドへの埋め込み（ライブデモが禁止されているため）
- 提出フォーム 1-4〜1-7（連絡担当者・メールアドレス・学生賞対象）の入力
