# PDR-008: 平均値は内部利用にとどめ、制度上限値のみ可視化する

**Date**: 2026-08-22
**Status**: 採用済み
**Owner**: プロダクトオーナー / AI Coding Agent

---

## 背景

プロダクトオーナー（妻）から、オープンデータ活用機能について次の指摘があった。

> 平均を出したら平均と比べて遅れていたら確実に焦るからやめないと。

PDR-006 と `PRODUCT_VISION.md` の Value 1（*Compass, not a Mirror*）は「他ユーザーとの比較・SNS機能を作らない」を明確に禁じていたが、**アプリが提示する統計データ自体（平均値）と比較して焦る**という経路は塞げていなかった。実際 `docs/hackathon/SUBMISSION_PLAN.md`（Phase 1.5）は「第一子平均出産年齢 約30.8歳などの参考値バンドをタイムライン上に重ねる」という具体的な実装を計画しており、これは平均という軸を画面に出す設計そのものだった。相手が実在の他人かオープンデータの平均値かの違いだけで、「自分の位置を軸に対して引き算できてしまう」という焦りの発生機序は同じであるため、この計画は撤回する。

一方でユーザーからは次の2点も同時に示された。

1. **テンプレート機能とその初期値にはユーザビリティ上の必要性があり、統計を内部的に使うのは問題ない**（明示的に可視化しなければよい）
2. **平均値ではなく、制度上の上限値（例: 育休の取得上限）は積極的に出したほうがよい**

この2点を踏まえ、統計・数値データの扱いを3〜4分類に整理し、可視化してよいものとだめなものを切り分ける。

---

## 決定事項

### データの分類と扱い

| 種別 | 例 | 扱い |
|---|---|---|
| A. 実態の中心値（平均・中央値・最頻値） | 第一子平均出産年齢、育休期間の最頻値 | **UI に出さない。** テンプレート／カタログ初期値の内部的な根拠としてのみ使う |
| B1. 出来事起点の相対的な上限 | 育休は子が2歳まで、産後ケア事業は産後1年未満、助成の申請期限は治療終了年度末まで | **出典付きで積極的に出す。** 本 PDR の主対象 |
| B2. 誕生日起点の絶対的な年齢上限 | 不妊治療助成の年齢要件など、暦年齢そのものに紐づく上限 | **出さない。** 形は上限でも「あと何年」を突きつけ、A と同じ焦りを生む |
| C. 実態の分布・選択肢の存在 | 出産後に就業継続／転職／離職という選択肢がある事実 | 割合の数値は出さず「選択肢が存在する」ことだけを示す。今回はスコープ外（→ Issue 化） |

一行ルール: **平均は「他人がどうだったか」、上限は「あなたに何が許されているか」。前者は比較を生み、後者は選択肢を増やす。**

B1 と B2 を分けたのが今回の要点。上限という形であっても、暦年齢に貼り付いた上限（B2）は「残りが減っていく」という感覚を生み、A と同じ失敗を繰り返す。安全なのは、出来事（育休開始、治療終了など）からの相対距離で表現できる上限（B1）に限る。

**金額の上限は出さない。** 助成額や手当額は B1 の形（上限額）を取ることがあるが、`PRODUCT_VISION.md` の意図的スコープ外「年収・給付金などの財務シミュレーション（計算の正確性に責任を持てない）」に抵触する。制度の存在と期間の上限だけを示し、金額には触れない。

### 実装方針

- A は Dart の const 定数として dartdoc に出典を残し、`presentation/` からの参照を禁止する（内部専用であることをコードでも示す）
- B1 は出典（データセット名・提供元・URL・取得日・根拠法令）付きの値オブジェクトとして持ち、既存の制約チェック（`ConstraintSeverity.info`）の経路に乗せて表示する。警告色にせず、配置をブロックしない（Value 4 は維持）
- 実行時に外部 API へ動的通信する設計は採らない（PDR-006 の判断を踏襲）。開発時にオープンデータを抽出し、静的な Dart 定数として組み込む

## PDR-006 からの変更点

- **Phase 1.5「参考値バンドをタイムライン上に重ねる」を撤回する。** 平均値を軸としてタイムライン上に表示する実装は行わない
- `career_stats_master.json`（PDR-006:52 が計画していた、平均値を含む実行時マスタ）は作らない。代わりに A は内部専用の Dart 定数、B1 は出典付きで可視化する値オブジェクトに分けて持つ
- **採用データセットの訂正**: PDR-006:45 が挙げていた東京都『東京の男女平等参画データ』(`t313360d0000000053`) は2017年版で更新が止まっており、B1 に該当する上限値も含まないため使わない。代わりに**東京デジタル2030ビジョン（こどもDX）子育て支援制度レジストリ**(`t000029d0000000034`、CC BY、データ時点2025-08-20) を主データセットとする。都・区市町村の子育て支援制度が構造化JSON（対象年齢の上限・根拠法令を含む）で公開されており、B1 の抽出元として適している
- PDR-006:44 の「第一子平均出産年齢 約30.8歳」は、確認したところ出典CSV（『次世代育成支援東京都行動計画』`t000054d0000000184`）の平成19年（2007年）までの系列の値だった。この値は A（内部利用のみ）に分類されるため実害はないが、内部の初期値算出に使う場合は最新の統計に差し替えるべき（→ Issue 化）

## 検討したが採らなかった案

1. **平均値を小さく・控えめに表示する**
   採らなかった理由: 大きさの問題ではなく、軸として画面に存在するかどうかが問題。控えめに出しても、ユーザーが自分の値との引き算をできてしまう時点で機序は同じ。
2. **平均値は出すが、自分の値との差分は計算・表示しない**
   採らなかった理由: 差分計算はユーザーの頭の中で行われるものであり、アプリ側の実装で防ぐことができない。
3. **実行時に外部データポータルへ動的アクセスする設計（PDR-006 で既に不採用）**
   踏襲。開発工程での静的抽出のほうが精度・速度・堅牢性で優れるという PDR-006 の判断を継続する。
4. **年齢上限（B2）も出来事起点の上限と同様に可視化する**
   採らなかった理由: 「何歳まで」という表現は暦年齢に対する焦りを直接刺激する。過去に Issue #63（「自然妊娠期間（35歳まで）」を参考値候補に入れない判断）で同種の判断が既に一度なされている。今回はその判断を一般化し、B2 全体を非表示とした。
