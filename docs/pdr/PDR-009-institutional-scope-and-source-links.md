# PDR-009: 制度上限に実施主体ラベルと出典リンクを追加し、対象を拡充する

**Date**: 2026-08-23
**Status**: 採用済み
**Owner**: プロダクトオーナー / AI Coding Agent

---

## 背景

PDR-008・#96 で「制度上の上限値は出典付きで積極的に出す」という方針を実装したが、プロダクトオーナーから
次の指摘があった。

> ・その制度が国の制度なのか、都の制度なのか、区の制度なのか、みたいなところ（目的は、自分が対象になるのか
>   みたいな気づきを得たい。）はわかった方が良い。
> ・その制度について詳しく知るためのリンク（クリックしたら制度の公式ページに飛ぶ）くらいの案内はあった方が良い。

調査の結果、次の3点が判明した。

1. `DataSource.publisher`（データの提供元）はあるが、**実施主体を表す項目が無い**。産後ケア事業は
   実施主体が区市町村・データ提供元が東京都で、両者はそもそもズレうる。
2. `DataSource.url` は値としては存在するが `lib/` のどこからも読まれておらず、クリックできる導線が無い。
3. 制度上限が3件しかなく、うち2件が国の制度・1件が区市町村の制度で、実施主体を出しても弁別に乏しい。

さらに、**既存の出典URLが2本（育休・産休）とも404で切れていた**ことと、産後ケア事業の出典に使っている
東京都子育て支援制度レジストリ（`t000029d0000000034`）が、国のレジストリ公開に伴い**更新を終了している**
（データ時点 2025-08-20）ことが調査で判明した。

---

## 決定事項

### 実施主体は「国」「東京都」の2値のみ

「自分が対象になるかの気づき」という目的に対して、区市町村単位の粒度は過剰と判断した。

- 産後ケア事業は母子保健法という国の法律に基づく法定事業のため `国` に分類し、
  実施主体が区市町村である旨は `message` の文中に1文で含める（専用のラベルは作らない）。
- 将来的に区市町村単位の制度（保育所の入所申込等）を大量に扱うようになった場合は、この判断を見直す。
  その場合は本 PDR に `Superseded by` を追記する。

### 出典URLは全エントリで必須にする

`institutional_limits_test.dart` で `source.url` が non-null であることをアサートし、
「リンクがあるかもしれない」ではなく「制度情報には必ず公式ページへの導線がある」を保証する。
出典URLを開く仕組み自体（`url_launcher` の導入）は [ADR-026](../adr/026-url-launcher.md) を参照。

### 年齢要件（B2）は引き続き出さない。対象かどうかの判断はリンク先に委ねる

PDR-008 の B2（暦年齢に紐づく上限）方針は変更しない。たとえば東京都不妊検査等助成事業には
年齢要件があるが `message` には含めず、「対象になるかどうか」の最終確認は出典リンクの公式ページに任せる。
これは「気づきを得たい」という今回の要望と矛盾しない — アプリ側が年齢を突きつけるのではなく、
制度の存在と申請期限（B1）だけを示し、詳細確認への入口を用意する。

### 追加する制度は既存の `duration` / `window` の2 kind で表現できるものに限る

`institutional_limit_check.dart` の判定ロジックは変更しない。育児・介護休業法から
「回数」（育休の分割取得2回など）や「開始点付きの区間」（3歳〜就学前の柔軟な働き方の措置など）は、
既存の2 kind では表現できないため今回は見送る。

### 出典の差し替え・訂正

| id | 変更 |
|---|---|
| `IL-childcare-leave` | 出典URL差し替え（404 → 厚労省の育児休業制度特設サイト） |
| `IL-maternity-leave` | 出典URL差し替え（404 → 厚労省「働く女性の心とからだの応援サイト」） |
| `IL-tokyo-fertility-test-subsidy`（新規） | レジストリのスナップショット値（申請期限1年・年齢要件43歳未満）ではなく、
  東京都福祉局の公式ページの現行値（申請期限2年・年齢要件40歳未満）を採用する。理由は上述のとおり
  レジストリが更新終了しているため。 |

## 追加した制度

キャリアプラン検討への寄与を基準に選定した。育児・介護休業法は出産・子育てに伴う働き方の制約を
出来事起点（B1）で示せる制度がまとまっており、東京都子育て支援制度レジストリ（302種類・7,812件、
63自治体）は母子保健・給付が中心でキャリア判断への寄与は薄いと判断し、今回は都のデータから
1件（不妊検査等助成事業の申請期限）のみを採用した。

| id | catalogId | 実施主体 | 内容 |
|---|---|---|---|
| `IL-paternity-leave` | `childbirth` | 国 | 産後パパ育休（出生後8週間以内に4週間、2回分割可） |
| `IL-overtime-limit` | `childbirth` | 国 | 所定外労働の制限・時間外労働の制限（小学校就学の始期まで） |
| `IL-child-nursing-leave` | `childbirth` | 国 | 子の看護等休暇（小学校3年生の修了まで） |
| `IL-short-working-hours` | `return-to-work` | 国 | 短時間勤務等の措置（子が3歳になるまで） |
| `IL-tokyo-fertility-test-subsidy` | `fertility-treatment` | 東京都 | 不妊検査等助成事業（検査開始日から2年以内に申請） |

所定外労働の制限・時間外労働の制限（`IL-overtime-limit`）は2025年4月施行の改正で対象が
「3歳未満」から「小学校就学の始期まで」に拡大されており、子の看護等休暇も同時期に対象が
「小学校就学前」から「小学校3年生の修了」に拡大されている。この拡充自体が「知らないと機会を
逃す」情報であるため、今回優先して採用した。

---

## 検討したが採らなかった案

1. **実施主体を enum ではなく自由記述の1行にする**
   採らなかった理由: 表記ゆれが起きやすく、後から絞り込みや対象判定に使えない。件数がまだ少ない今のうちに
   構造化しておく。
2. **産後ケア事業を区市町村扱いにして enum を3値にする**
   採らなかった理由: 「国/東京都/区市町村」の3値化は将来的な拡張の選択肢として残すが、
   現時点で区市町村の制度が1件（それも法定事業）しかない状態で3値目を作る実益が薄い。
3. **東京都子育て支援制度レジストリの残り301種類から追加でキャリア寄与の制度を探す**
   採らなかった理由: 認可保育所の申込等は自治体ごとに期限がバラバラで「◯か月」という数値の形に
   落とせず、既存の `duration` / `window` では表現できない。ロジック追加が要るため今回は見送り、
   Issue で扱う。
