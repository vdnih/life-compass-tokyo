# PDR-010: メッセージングの主語を「制度」から「本人」に戻す

**Date**: 2026-08-23
**Status**: 採用済み
**Owner**: プロダクトオーナー / AI Coding Agent

---

## 背景

`docs/hackathon/PRESENTATION_OUTLINE.md` の2026-08-23改定（PDR-006〜PDR-009の反映）で、表紙キャッチ
コピーを「制度上、選べる人生を描く」とした。これに対しプロダクトオーナーから次の指摘があった。

> キャッチコピー「制度上、選べる人生を描く」ってキャッチコピーは全然だめです。
> 決められたレールを歩く感じがして、本来やりたい、自分の生き方を考えるようなプロダクトとは逆の
> イメージになります。制度は賢く使い、それによって自分らしい生き方をする助けになれば。

続けて、プロダクトが目指す全体像が改めて示された。

> 家庭もキャリアも全力でがんばりたい女性にとって、世の中には様々な制約がある。結婚・妊娠・出産・
> 子育てなどでどうしてもキャリアに影響しかねない。
>
> そこで、日本、そして東京都の制度上どんなライフプランが選べるかを示すことで、自分の人生をどう
> したいか描けるようにした。適宜修正も可能なので、何度でも立て直せる。これを自分・そして家庭で
> 共有できるようになる。また、これを男性がやってみるプログラムをすることで女性の制約の多さを
> 痛感していただけるようになる。
>
> 重ねて、ここで得られるデータをもとに、東京都や国が女性を支援する施策が増加することを願う。
> （私自身、今世の中にあるデータで得られる示唆よりも、女性はもっと働きたいし社会で成功したいし、
> 起業したいくらい熱い層も多いのではないかと思っている。ただ、どうしても家庭との両立で諦めるを
> 得ない状況の人が多いと感じている。）

この全体メッセージ自体は `PRESENTATION_OUTLINE.md:14-22`（PDR-006〜009 反映時点）から変わっていない。
問題は全体メッセージではなく、**見出しコピーに落とし込む際の主語の選び方**にあった。

### なぜレール感が出たか

`PRODUCT_VISION.md` と `PRD.md` のビジョン・ミッションは一貫して「自分の人生を自分で描く」（本人が
主語）であり、制度は Value 1（Compass, not a Mirror）が言う「選べる余地」を示す道具として位置づけ
られている（`PRODUCT_VISION.md:57`）。ここに矛盾は無い。

矛盾していたのは `docs/hackathon/` 配下の見出しコピーだけだった。調査すると、表紙は
「制度上、選べる人生を描く」（**制度が主語**）で始まり、締めは「選べる余地をコンパスに、自分らしい
人生を描く」（**本人が主語**）で終わるという分裂を起こしていた。とくに強くレール感を出していたのは
以下の2箇所。

1. 「制度上、〜」という構文そのもの。「人生」を「制度上」という語が修飾する形になり、制度が
   人生の範囲を決めているように読める。
2. 「あなたに何が**許されている**か」という言い回し。出自は `PDR-008:37` の一行ルール
   「平均は『他人がどうだったか』、上限は『あなたに何が許されているか』」で、これは平均値との
   対比のための**内部的な表現**だった（当時は「制度が許可を与える」ことそのものが論点だった）。
   これがユーザー向けの見出しコピーに昇格した結果、上から許可を与えられる含意が前面に出てしまった。

---

## 決定事項

### 言い換えルール

資料横断で、以下のルールをメッセージング規約として確定する。**制度を文の主語・修飾語の先頭に
置かない。制度は本人が使う道具として、述語側に置く。**

| 直す前（制度が主語） | 直した後（本人が主語） |
|---|---|
| 制度上、選べる人生を描く | 制度を知って、自分の人生を自分で描く |
| 制度上、何が選べるかを出典付きで示す | 使える制度を、出典付きで手渡す |
| あなたに何が許されているか | あなたが使える権利はどこまでか |
| 制度上どんなライフプランが選べるかを示し | 使える制度を示すことで、どんなライフプランを描けるかが分かるようにし |

「選べる余地」「決めるのは自分」「権利」は既に本人が主語の表現なので、そのまま使ってよい。

このルールを `docs/hackathon/PRESENTATION_OUTLINE.md` の表紙・スライド3見出し・スライド3話す原稿・
締めの一文、および `docs/hackathon/SUBMISSION_DRAFT.md` の 2-3・2-4・4-1 に適用する。

### PDR-008 との関係

PDR-008 の**設計判断**（A: 平均は内部利用のみ／B1: 制度上の上限は出典付きで可視化する）は今回
変更しない。今回改訂したのは、その判断を説明する一行ルールの**表現**だけである。判断内容と
コピー表現は別物であり、後者がユーザー向けに一人歩きしたことが今回の問題だった。

---

## 検討したが採らなかった案

1. **「制度」という語を資料から全部外す**
   採らなかった理由: 出典付きの制度上限データはこのプロダクトの実装の中核（`InstitutionalLimit`、
   PDR-008・PDR-009）であり、ハッカソンの審査軸（オープンデータ活用）でもある。「制度」を隠すの
   ではなく、主語を入れ替えることで解決する方が実態に即している。
2. **`PRODUCT_VISION.md` / `PRD.md` を修正する**
   採らなかった理由: 調査の結果、両ドキュメントは一貫して本人主語のフレーミングであり、修正が
   必要な記述は見つからなかった。ズレていたのは `docs/hackathon/` の見出しコピーのみ。
